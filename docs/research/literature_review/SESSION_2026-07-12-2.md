## Implied direction

The main finding is a caution, not a new method. Every paper that clusters
players or matches (ShuttleNet, tennis match-type, tennis player-network,
ViSTec) clusters on playing STYLE, not skill. They all use elite-only
populations, so there is no skill gradient in the data for the clustering to
find, and the axes that separate the clusters are serve-versus-return style,
court surface, or technique choice. The tennis player-network paper is explicit:
it cannot separate "clay court specialists" from "lower level players." The
vertical-jump exemplar separates movement style, and its one honest validation
uses an external injury label.

So the literature does not show that unsupervised clustering separates skill
level without labels. Run on the project's per-player features (pose, stroke
mix, court zones), a clustering would most likely surface a mix of playing
style, handedness, and body type, with no guarantee the top axis is skill.

What does transfer is method recipes, not results:

1. **Feature reduction before clustering** (soccer paper, the one clear
   positive). Clustering of variables (CLV, around latent variables) groups
   correlated per-player metrics into a few dimensions, label-free, and it beat
   the expert grouping (Rand index 0.810). This is a usable pre-step for the
   project's many candidate metrics. It clusters variables, not players.

2. **The standard clustering loop** (jump exemplar and tennis match-type):
   scale features, prune correlated ones, k-means, choose k by elbow or
   silhouette, validate against an external label. Clean and cheap to copy. Note
   the tennis match-type paper's deep-learning step (BERT on tabular numbers)
   added almost nothing over plain PCA plus k-means (silhouette 0.406 vs 0.402),
   so do not reach for a neural embedding first.

3. **Reference-based scoring** (StanceScorer): score a player by distance to an
   exemplar's recording of the same shot. Needs no A/B/C/D labels, only a chosen
   reference and per-stroke alignment. A label-free scoring path distinct from
   clustering, though StanceScorer itself is a 2020 IMU proof of concept that
   never computes an actual score and has a confounded reference.

The load-bearing consequence for the project: unsupervised clustering alone is
unlikely to yield A/B/C/D levels. The project still needs an external anchor to
orient any clustering toward skill, which points back to the ground-truth
scoring scheme found in the first session (MultiSenseBadminton: coaches score
1-7 from video, average, bin, report kappa). Cluster to reduce and structure the
feature space; use a small set of graded anchors to name the skill axis.

## Lingering queries and observations

- Not one paper in the set had a skill gradient in its sample. The whole field
  clusters within a single elite tier. The project's club A/B/C/D setting is
  actually a better testbed for skill clustering than anything published here,
  which is an opportunity, not just a gap.
- Reference-based scoring (StanceScorer) and CLV feature reduction are the two
  ideas worth prototyping. They are complementary: CLV to build a few clean
  performance dimensions, then either cluster in that space or score against a
  reference exemplar per dimension.
- The recurring extraction blocker is the same as in session 1: the interesting
  outcome-linked features need rally-winner detection and forced-vs-unforced
  judgement, which the pipeline lacks.
- Quality caution repeats: the tennis match-type paper applies BERT off-label to
  27 tabular numbers with no tokenisation described, for a 0.004 silhouette gain.
  Neural framing here is decorative.
