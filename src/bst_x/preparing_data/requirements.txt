# Prepare training data: rtmlib pose extraction + collation into batch arrays.
# Python 3.11+ (validated on 3.13). Run once per dataset build, then switch to
# the BST training venv.
#
# The 2D extraction path (raw_extract.py, prepare_train_on_shuttleset's
# detect_players_2d) migrated off OpenMMLab onto rtmlib: onnxruntime-backed,
# numpy-2 clean, no source build, no separate-venv numpy<2 pin. Models:
# RTMDet-M person @640 + RTMPose-L body7 COCO-17 (model rationale:
# docs/architecture_notes/rtmlib_migration/README.md).
# Versions below are the set the migration gate ladder was validated against.
#
# --- Manual install steps (can't go in requirements.txt) ---
# CPU:  pip install -r requirements.txt
# GPU (production re-extract on the CUDA box): swap onnxruntime -> onnxruntime-gpu.
# 1.27.0 needs CUDA 13.x + cuDNN 9.x. The [cuda,cudnn] extras do NOT resolve (NVIDIA's
# cu13 toolkit wheels are renamed/unpublished), so take the toolkit from a system
# CUDA-13 module and pip-install cuDNN (it pulls the matching cublas/nvrtc):
#   pip install -r requirements.txt
#   pip uninstall -y onnxruntime && pip install onnxruntime-gpu==1.27.0
#   pip install "nvidia-cudnn-cu13~=9.0" --extra-index-url https://pypi.nvidia.com
#   (rtmlib installs the CPU onnxruntime, so confirm CUDAExecutionProvider is
#    present after the swap. Runtime note: LD_LIBRARY_PATH must include BOTH
#    site-packages/nvidia/cudnn/lib AND site-packages/nvidia/cu13/lib, exported
#    before python starts; the venv's bundled libs cover it with no system CUDA
#    module needed (verified bourbaki 2026-07-08). Missing libs do NOT error:
#    onnxruntime logs two red lines and silently runs CPU, ~10x slower.)
#
# torch is NOT required by the production raw_extract path (onnxruntime manages
# its own memory). It is needed ONLY if you run the secondary
# prepare_train_on_shuttleset module path (its dataset helpers import torch at
# module load); install any modern CPU/CUDA build separately, e.g.:
#   pip install torch --index-url https://download.pytorch.org/whl/cpu
# That same module path also imports beartype + jaxtyping at load (its
# signatures are shape-checked), so they ship as requirements below:
# pure-Python, needed by the G3/G5/G6 gates and the collate step, which all
# import prepare_train.
#
# requirements-legacy-3d.txt keeps the OpenMMLab env for the parked 3D pose
# stream design (the 3D code path was removed; see
# docs/archive/completed_general_refactors/structure_and_guards_pass/pose_3d_stream_design.md).
# Install it in a separate venv; its numpy<2 pin cannot coexist with the numpy>=2 here.

# rtmlib pose extraction (RTMDet + RTMPose over onnxruntime)
rtmlib==0.0.15                   # low-level RTMDet/RTMPose classes; pin (repo main drifts from PyPI)
onnxruntime==1.27.0              # CPU inference (deterministic); CUDA box: onnxruntime-gpu==1.27.0 + a CUDA-13 toolkit + nvidia-cudnn-cu13 (GPU steps above)

# Standard libraries
numpy==2.4.6                     # numpy-2 clean now that OpenMMLab is off the 2D path
opencv-python==4.13.0.92         # cv2: video decode + the RGB-fix cvtColor in the adapter
pandas==3.0.3                    # collation; G5 verified identical downstream output on 3.0.3 (exact _failed, floats at atol 1e-5)
scipy==1.17.1                    # court projection / geometry helpers
tqdm==4.68.3                     # progress bars
parse==1.22.1                    # pure Python, no deps

# prepare_train_on_shuttleset module path (shape-checked signatures; see note above)
beartype==0.22.9                 # runtime checker for the jaxtyping annotations
jaxtyping==0.3.11                # shape annotations on the pose/collate helpers
